# FileLink 数据库迁移设计

## 1. 目标

FileLink 使用 dbmate 管理 MySQL Schema。C++ 服务只读写业务数据，不负责：

- 在启动时创建或修改表；
- 扫描 SQL 文件；
- 记录已经执行的 migration；
- 实现 migration 回滚器。

这样数据库结构可以独立版本化，也避免把部署逻辑混入服务启动流程。

## 2. 为什么选择 dbmate

dbmate 是一个独立、语言无关的迁移工具，支持：

- 使用普通 SQL 描述变更；
- 按版本顺序执行 migration；
- 使用 `schema_migrations` 记录已执行版本；
- 查询状态和回滚最近一次 migration；
- 以单个 Docker 容器运行。

FileLink 不需要在 C++ 中链接 dbmate。迁移容器执行完成后退出，不进入线上请求链路。

## 3. 为什么不用 MySQL 初始化目录

MySQL 镜像只会在数据目录为空时执行 `/docker-entrypoint-initdb.d`。已有 Named Volume 不会因为新增 SQL 文件而再次执行初始化脚本，因此它适合首次引导，不适合持续演进 Schema。

dbmate 会查询 `schema_migrations`，每次只执行尚未应用的版本，适用于已有数据库。

## 4. 为什么不让 FileLink 自动迁移

应用启动时自动修改 Schema 会把两个职责绑定在一起：

```text
启动 HTTP 服务
+ 修改数据库结构
```

当 migration 失败时，服务启动错误会同时混合配置、网络、权限和 DDL 问题；多实例部署还可能让多个进程竞争执行迁移。

FileLink 采用显式的一次性命令：

```bash
docker compose run --rm migrate
```

开发环境、测试环境和部署流程都执行同一个命令。未来若将 FileLink 服务也放入 Compose，应让服务依赖 migration 成功，而不是在 C++ `main()` 中执行 DDL。

## 5. Compose 边界

`migrate` 服务：

- 使用固定版本的 dbmate 镜像；
- 等待 MySQL healthcheck 成功；
- 只读挂载 `db/migrations`；
- 执行完毕后正常退出；
- 不配置自动重启。

dbmate 使用 URL 连接 MySQL。当前 Compose 直接复用 `FILELINK_MYSQL_PASSWORD`，因此开发密码限制为 URL-safe 字符：

```text
A-Z a-z 0-9 - _
```

如果未来必须支持任意特殊字符，应单独提供经过 percent-encoding 的 migration URL，不能把编码后的密码直接传给 MySQL 容器。

## 6. Migration 规则

文件放在：

```text
db/migrations/<version>_<description>.sql
```

每个文件必须包含：

```sql
-- migrate:up

-- migrate:down
```

规则：

1. 已应用的 migration 不再修改；修正 Schema 时新增下一个版本。
2. 一个 migration 只完成一个相关的 Schema 变化。
3. `down` 只用于开发回退，生产环境优先使用新的前向 migration。
4. 不在 migration 中写入依赖外部服务的业务数据。
5. 先备份重要数据，再执行破坏性 DDL。

## 7. MySQL DDL 的事务边界

MySQL 8.4 的单条 InnoDB DDL 可以具备原子性，但 DDL 会隐式提交，不能把包含多个 DDL 的 migration 当作一个可以整体回滚的普通事务。

因此 FileLink 的 DDL migration 显式使用：

```sql
-- migrate:up transaction:false
```

dbmate 仍然负责版本排序和记录，但不能替代对每条 DDL 可恢复性的设计。

## 8. 首个 Schema

`upload_sessions` 保存可靠上传的协议事实：

```text
upload_id
state
total_size
committed_offset
expected_hash
content_hash
expires_at
```

关键约束下沉到数据库：

- `committed_offset` 不能超过 `total_size`；
- `state` 只能取状态机定义的值；
- `COMPLETED` 必须具有服务端内容 Hash；
- `(state, expires_at)` 支持后台扫描过期会话。

数据库约束是最后一道防线，不能替代 C++ 服务中的输入校验和状态迁移检查。

## 9. 常用命令

```bash
# 执行所有待处理 migration
docker compose run --rm migrate

# 查看 migration 状态
docker compose run --rm migrate status

# 回滚最近一次 migration，仅用于确认安全的开发环境
docker compose run --rm migrate rollback
```

## 10. 面试回答

### 为什么使用 dbmate，不在 C++ 中写 migration runner？

Migration 是数据库部署能力，不是 FileLink 的业务竞争力。dbmate 已经解决版本发现、执行顺序和历史记录，FileLink 没有理由重新实现。C++ 代码只保留上传状态机和数据访问。

### 为什么不使用 `/docker-entrypoint-initdb.d`？

初始化目录只在空数据目录首次启动时执行，无法升级已经存在的 Named Volume。dbmate 根据版本表增量执行，能够覆盖持续演进场景。

### dbmate 能让 MySQL DDL 整体回滚吗？

不能。MySQL DDL 会隐式提交。dbmate 管理的是迁移版本和执行流程，DDL 的拆分、兼容性与失败恢复仍然需要单独设计。
