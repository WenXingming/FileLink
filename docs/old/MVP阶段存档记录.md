# FileLink MVP 阶段存档记录 (Save Point)

## 🎯 目前已达成的核心成就
1. **基于内容寻址的可靠存储底座**
   - 彻底摒弃了传统网盘的混乱目录结构，使用 BLAKE3 高速哈希实现了类似 Git 的 `objects/ab/cd/...` 分级目录存储。
   - 实现了基于硬件级硬链接 (`link`/`unlink`) 的原子发布，保证了高并发下的数据完整性。
2. **前后端完全贯通的闭环链路**
   - **上传 (`POST /upload`)**：支持边落盘边计算哈希，返回带正确扩展名的分享链接。
   - **下载 (`GET /objects/{hash}.ext`)**：服务端智能剥离后缀并返回正确的 `Content-Type`，让浏览器可以直接预览图片，保存时也不丢失扩展名。
   - **页面托管 (`GET /`)**：内建了静态页面支持，直接通过 C++ 后端托管了双主题（深色/浅色）的精美前端页面。
3. **极简架构与零依赖**
   - 整个流程**没有依赖任何数据库**，全凭巧妙的设计（内容寻址 + URL 后缀透传）解决了一系列体验痛点，将架构复杂度和维护成本降到了最低。
4. **坚不可摧的测试网**
   - 全链路拥有 43 个自动化测试用例，从底层的 Hash 算法防碰撞、重复文件判定，一直覆盖到了服务端的 HTTP 存取集成测试，100% 稳定绿灯通过。

## 🗺️ 未来可以演进的方向 (演进路线图)

### 分支 A：技术硬核深度 (Infrastructure) —— Tudou 框架流式重构
- **现状**：目前 Tudou 框架是“全内存缓冲”，即大文件会被完全读进内存。
- **下一步**：修改 Tudou 源码，引入“流式路由（Streaming Route）”，并通过 Linux `sendfile` 系统调用实现网卡级别的零拷贝下载，彻底打通 GB 级超大文件的极速传输。

### 分支 B：业务广度 (Business) —— 引入 SQLite 元数据管理
- **现状**：目前网盘只认 Hash，是一个纯粹的匿名对象存储。
- **下一步**：接入 SQLite，建立 `前端文件名 -> 真实 Hash -> 上传者/上传时间` 的映射关系。进而可以开发“文件列表页”、“文件夹嵌套”、“网盘登录态与隔离”等完整的网盘核心业务系统。
