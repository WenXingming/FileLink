# 本地部署、测试与演示脚本

这份文档的目标不是罗列命令，而是让你在面试前能稳定完成一条演示：启动服务、展示用户操作、指出背后的设计，并在需要时用测试证明关键边界。

## 0. 演示前准备

需要 Docker Compose、CMake 3.25+、C++ 编译器，以及 MySQL 客户端开发包、libsodium、hiredis 等构建依赖。服务默认监听 `http://127.0.0.1:18081`。

首次准备开发环境：

```bash
cp .env.example .env
# 编辑 .env：为 MYSQL_ROOT_PASSWORD 和 FILELINK_MYSQL_PASSWORD 设置本地密码

docker compose up -d mysql
docker compose run --rm migrate

cmake -S . -B build \
  -DFILELINK_BUILD_TESTS=ON \
  -DFILELINK_BUILD_INTEGRATION_TESTS=ON \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```

`docker compose` 只提供 MySQL、可选 Redis 和可选 Nginx；C++ 服务本身由本机构建产物运行。`migrate` 会执行 [`database/migrations/`](../database/migrations/) 中的初始 schema。开发数据可随时用 `docker compose down -v` 销毁，但这会同时删除 MySQL 与 Redis 卷。

启动服务：

```bash
./scripts/run-dev.sh
```

脚本会加载未提交的 `.env`、使用 `config/server.toml`，并启动 `build/src/filelink-server`。浏览器访问 `http://127.0.0.1:18081`；健康检查为：

```bash
curl http://127.0.0.1:18081/health
# {"status":"ok"}
```

## 1. 测试基线

先执行不依赖外部服务的单元测试：

```bash
ctest --test-dir build -L unit --output-on-failure
```

再加载本地密码运行 MySQL 集成测试：

```bash
set -a; source .env; set +a
FILELINK_TEST_MYSQL_PASSWORD="$FILELINK_MYSQL_PASSWORD" \
FILELINK_TEST_MYSQL_PORT="$MYSQL_HOST_PORT" \
ctest --test-dir build -L integration --output-on-failure
```

Redis 默认关闭。需要演示缓存或运行 Redis 测试时：

```bash
docker compose --profile cache up -d redis
./scripts/run-dev.sh --redis-enabled

FILELINK_TEST_REDIS_PORT="$REDIS_PORT" \
FILELINK_TEST_MYSQL_PASSWORD="$FILELINK_MYSQL_PASSWORD" \
ctest --test-dir build -L integration --output-on-failure
```

应这样解释测试层次：unit 测试验证配置、对象存储和密码哈希；integration 测试验证 MySQL 事务、TUS、权限、分享、Redis 回退、回收器及真实 HTTP 进程。Redis 不可用时服务会回查 MySQL，不是测试失败条件。

## 2. 十分钟浏览器演示

演示前在项目根目录准备一个小文件和一个较大的测试文件。大文件便于直观看到暂停/续传：

```bash
printf 'FileLink demo\n' > demo.txt
dd if=/dev/zero of=resume-demo.bin bs=1M count=128
```

### 1–2 分钟：注册与私有文件库

1. 打开首页，选择“创建账户”，输入例如 `alice_demo` 和密码，完成注册。
2. 说明注册成功后并没有把 token 放进 localStorage：浏览器收到的是 `HttpOnly` Cookie；MySQL 只保存其 BLAKE2b 哈希。
3. 展示空文件列表，说明该列表来自 `GET /files`，不是前端本地历史记录。

可以在浏览器开发者工具的 Application/Storage 面板展示 Cookie 属性，但不要显示或复制真实 token。

### 3–5 分钟：上传、暂停与恢复

1. 选择 `resume-demo.bin`，开始上传；中途点击“暂停”。
2. 再点击“断点续传”，观察进度从服务器确认的偏移继续，而不是从 0 开始。
3. 上传完成后，列表出现一个逻辑 File；点击下载，确认浏览器获得原文件。

讲述重点：前端保存上传会话 URL，恢复前通过 `HEAD` 获得 `Upload-Offset`；后端把分片写到 `.part` 文件并流式计算 BLAKE3，最后原子发布 Object，再在 MySQL 事务中创建 File。

### 6–7 分钟：私有性与分享

1. 在已上传文件的操作区点击“分享”，选择 7 天，创建并复制公开链接。
2. 在无痕窗口打开链接，证明无需登录也能下载。
3. 回到原窗口撤销分享，再刷新无痕窗口，应该得到 `404`。
4. 可选：在另一个浏览器配置文件注册 Bob，尝试直接访问 Alice 的 `/files/<fileId>/download`；服务同样返回 `404`，不会泄露文件存在性。

讲述重点：公开授权绑定的是 File，不是 Object；创建分享时原始 token 仅返回一次，数据库只存 BLAKE2b 哈希，因此按内容哈希不能绕过权限。

### 8–10 分钟：删除与最终回收

1. 删除 Alice 的文件，列表立即消失。
2. 说明这只删除逻辑 File 并递减 Object 引用；最后一个引用归零后 Object 变为 `PENDING_DELETE`，物理字节不会在用户请求中立即删除。
3. 在另一个终端执行离线回收：

```bash
./scripts/run-dev.sh --reclaim-pending-objects
```

讲述重点：回收器用 `PENDING_DELETE → RECLAIMING` 认领对象；新上传若遇到已认领对象，其完成会话会失败，客户端可重新发起上传，而不会复活对象后又被回收器删除。

## 3. 可选：用 TUS API 展示秒传

网页端当前不会计算 `expected_hash`，因此 UI 演示的是“上传完成后的最终物理去重”。要展示创建会话时直接完成的秒传，可在已有 `demo.txt` 已经上传为 Object 后，使用支持 BLAKE3 的命令行工具 `b3sum` 和 curl：

```bash
base=http://127.0.0.1:18081
username=alice_api_demo
password=correct-password

curl -c /tmp/filelink-cookie.txt -sS -X POST "$base/auth/register" \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"$username\",\"password\":\"$password\"}"

hash=$(b3sum demo.txt | awk '{print $1}')
filename=$(printf 'copy-of-demo.txt' | base64 -w0)
expected_hash=$(printf %s "$hash" | base64 -w0)

curl -b /tmp/filelink-cookie.txt -i -X POST "$base/uploads" \
  -H 'Upload-Length: 14' \
  -H "Upload-Metadata: filename $filename,expected_hash $expected_hash"
```

前提是 `demo.txt` 的确为 14 字节且相同内容已在当前 `storage/` 中存在；否则应将 `Upload-Length` 改为 `stat -c%s demo.txt` 的结果。响应中的 `Location` 指向一个已完成的 UploadSession，随后 `GET <Location>` 会返回 `COMPLETED` 和新的 `file_id`。这展示的是：不传重复字节也会为当前用户创建独立 File，并增加 Object 的引用计数。

演示结束后删除临时 Cookie：

```bash
rm -f /tmp/filelink-cookie.txt demo.txt resume-demo.bin
```

## 4. 离线维护命令

这些命令执行一次任务后立即退出，适合由 cron 或 systemd timer 调度：

```bash
# 清理过期且仍处于 UPLOADING 的会话及其 .part 文件
./scripts/run-dev.sh --cleanup-expired

# 回收零引用、待删除的 Object
./scripts/run-dev.sh --reclaim-pending-objects

# 先只读列出磁盘有、objects 表无记录的孤儿对象
./scripts/run-dev.sh --scan-orphaned-objects

# 确认扫描结果后删除孤儿对象
./scripts/run-dev.sh --reclaim-orphaned-objects
```

不要把孤儿删除命令作为每次上传后的同步步骤；它会扫描对象目录，属于故障补偿与运维任务。

## 5. 演示时的顺序与追问

| 看到的现象 | 立即说明的设计点 | 可能追问 |
| --- | --- | --- |
| 注册后刷新仍登录 | HttpOnly Cookie + 服务端会话 | 为什么不是 JWT？ |
| 暂停后恢复进度 | TUS offset 是服务端确认的事实 | 如何防止重复分片？ |
| 同内容生成不同文件名 | File/Object 分层 | 去重会不会泄露数据？ |
| 无痕窗口能下载分享 | Share 是可过期授权 | 撤销如何即时生效？ |
| 删除后马上从列表消失 | 先删除业务所有权 | 为什么不立即删磁盘？ |
| 离线回收命令 | 状态机与补偿式清理 | 进程崩溃怎么处理？ |

回答不确定的实现细节时，回到已验证的事实：MySQL 是元数据真相来源；Redis 可失效；Object 用内容哈希定位；File 承载所有权；跨文件系统与数据库的窗口由离线补偿收敛。

## 演示前检查清单

- `.env` 未提交，且 MySQL 已健康、迁移已执行。
- `./scripts/run-dev.sh` 能启动，`/health` 返回 200。
- 浏览器使用一个干净账户；无痕窗口用于公开分享验证。
- 预先准备大文件，避免现场生成文件耗时。
- 不展示 `.env`、Cookie token、数据库密码或完整连接串。
- 若要演示秒传，提前确认系统已存在相同内容的 Object，并准备 `b3sum`。

完成一次演示后，建议运行完整 integration 测试作为收尾证据，而不是手工修改数据库来“制造成功结果”。
